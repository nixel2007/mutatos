# mutatos

Мутационное тестирование для OneScript.

Покрытие показывает, какие строки выполнялись во время тестов. Оно не отвечает на главный вопрос: а заметят ли тесты, если код начнёт работать неправильно? Мутационное тестирование отвечает — оно вносит в исходники небольшие изменения и смотрит, упадут ли тесты.

Если после замены `>` на `>=` все тесты остались зелёными, значит граница условия ничем не проверена, хотя строка и была покрыта.

## Установка

```sh
opm install mutatos
```

## Использование

```sh
mutatos run
```

По умолчанию мутируются исходники из `./src`, а тесты запускаются командой `oneunit` в текущем каталоге.

```sh
mutatos run -d src/core -p . --json out/mutations.json --min-score 70
```

| Опция              | Назначение                                                                    |
| ------------------ | ----------------------------------------------------------------------------- |
| `-d, --directory`  | Каталог с мутируемыми исходниками, повторяемый. По умолчанию `./src`          |
| `-f, --file`       | Отдельный мутируемый файл, повторяемый                                        |
| `-p, --project`    | Каталог проекта, в котором запускаются тесты. По умолчанию текущий            |
| `--timeout-factor` | Во сколько раз мутанту дают больше времени, чем исходному прогону. По умолчанию 3 |
| `--json`           | Путь к файлу отчёта в формате JSON                                            |
| `--min-score`      | Минимальный индекс мутаций в процентах, иначе команда завершается с ошибкой   |

```
    строка 21, Максимум: возвращаемое значение заменено на Неопределено
    строка 28, ВходитВДиапазон: И заменено на Или
    строка 28, ВходитВДиапазон: >= заменено на >
    строка 28, ВходитВДиапазон: <= заменено на <

```

Ценность не в проценте, а в списке выживших: каждая строка — поведение, которое можно сломать, не уронив ни одного теста.

Пример из вывода лежит в репозитории: `examples/калькулятор` — калькулятор с намеренно неполными тестами.

## Мутаторы

| Мутатор           | Что делает                                                    |
| ----------------- | ------------------------------------------------------------- |
| `Арифметика`      | `+` ↔ `-`, `*` ↔ `/`, `%` → `*`                                |
| `Условия`         | `>` → `>=` и `<`, `<` → `<=` и `>`, `=` → `<>`, `<>` → `=`     |
| `Логика`          | `И` ↔ `Или`                                                    |
| `БулевыЛитералы`  | `Истина` ↔ `Ложь`                                              |
| `Возврат`         | `Возврат <выражение>` → `Возврат Неопределено`                 |
| `УдалениеВызова`  | удаляет вызов процедуры целиком                                |

### Свой мутатор

Мутатор — класс с аннотацией `&Мутатор`. Контейнер находит его сам, ничего регистрировать не нужно:

```bsl
&Мутатор
Процедура ПриСозданииОбъекта(&Пластилин Токены)
КонецПроцедуры

Функция Имя() Экспорт
	Возврат "МойМутатор";
КонецФункции

Функция ТипыУзлов(Типы) Экспорт
	Результат = Новый Массив();
	Результат.Добавить(Типы.ВыражениеБинарное);
	Возврат Результат;
КонецФункции

Функция Мутации(Узел, Контекст) Экспорт
	Мутации = Новый Массив();
	Мутации.Добавить(Контекст.МутацияТокена(Имя(), Узел.Операция, "+", "заменено на +"));
	Возврат Мутации;
КонецФункции
```

`Контекст` умеет создавать мутации по токену (`МутацияТокена`) и по узлу целиком (`МутацияУзла`), а также отдавать текст исходника для токена и узла.

## Как это устроено

1. Исходник разбирается [osparser](https://github.com/oscript-library/osparser) в синтаксическое дерево.
2. Дерево обходится, каждый узел показывается мутаторам, подписанным на его тип.
3. Мутация — это координаты замены в тексте: позиция, длина и новый текст. Мутант собирается из оригинала применением ровно одной мутации.
4. Мутант записывается на место исходника, запускаются тесты, файл восстанавливается — в любом случае, даже если прогон сорвался исключением.
5. Упавшие тесты означают, что мутант убит; зелёные — что выжил.

Перед прогоном мутантов запускаются исходные тесты: на красном проекте убитого мутанта не отличить от изначально сломанного кода. Длительность этого прогона задаёт таймаут мутантам, иначе зациклившая мутация висела бы вечно.

## Разработка

```sh
opm install -l --dev
./oscript_modules/bin/oneunit e -d tests
```

Прогон самого mutatos на подопытном проекте:

```sh
oscript src/cli/main.os run -p examples/калькулятор
```
