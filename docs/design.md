# mutatos — проектирование

Мутационное тестирование для OneScript в духе pitest. Тестовый фреймворк — OneUnit (на базе autumn).

## 1. Почему это вообще возможно (результаты исследования)

### osparser — готовый инструмент для мутаций

`osparser` (`ПарсерВстроенногоЯзыка`, opm-пакет) даёт всё необходимое:

- **AST с точными координатами**: у каждого узла есть поля `Начало` и `Конец` — ссылки на строки
  таблицы токенов с колонками `Позиция` (абсолютное смещение), `Длина`, `НомерСтроки`, `НомерКолонки`.
- **Visitor-плагины**: плагин объявляет `Подписки()` вида `ПосетитьВыражениеБинарное`,
  получает узлы при обходе (`Парсер.Посетить(...)`), имеет доступ к стеку родителей (`Стек()`).
- **Механизм точечных замен вместо перегенерации кода**: плагин пишет строки в `ТаблицаЗамен()`
  (`Позиция`, `Длина`, `Текст`), а `Парсер.ВыполнитьЗамены()` возвращает изменённый исходник.
  Остальной файл сохраняется байт-в-байт — минимальный дифф, точный маппинг мутанта на строку/колонку,
  никакой возни с восстановлением форматирования и комментариев.
- Токены операций уже классифицированы: `ЗнакСложения`, `ЗнакМеньше`, `ЗнакМеньшеИлиРавно`,
  `ЗнакРавно`, `ЗнакНеРавно` и т.д. — готовые цели для мутаторов.

Альтернативы отклонены:

- *C#-AST движка OneScript* (`OneScript.Language`) не экспонирован в язык, а его `CodeRange`
  хранит только начало узла без конца и смещения — для перезаписи исходника не годится без
  доработки движка и внешней компоненты.
- *Регэкспы* — ложные срабатывания в строках/комментариях, двуязычные ключевые слова; не вариант.
- *Токен-уровень* (`Парсер.Токенизировать()`) — пригоден как быстрый деградированный режим,
  оставляем как запасной вариант для файлов, которые osparser не смог разобрать.

### OneUnit — готовый исполнитель тестов

- CLI: `oneunit e -d <каталог> | -f <файл> -m <метод> -s <набор>` — фильтры-регэкспы позволяют
  запускать подмножество тестов для конкретного мутанта.
- **Exit code**: 0 — все тесты прошли (мутант ВЫЖИЛ), ≠0 — есть падения (мутант УБИТ).
  Для классификации мутанта достаточно кода возврата (`--mode none`, без отчётов — быстрее).
- `--timeout <мс>` — защита от мутантов, создающих бесконечные циклы.
- **Покрытие**: `--genericCoverage` / `--cobertura` (библиотека `coverage`, `oscript -codestat`) —
  построчное покрытие для отсечения мутантов в непокрытом коде.
- Двухпроцессная архитектура OneUnit (CLI генерирует точку входа и запускает дочерний `oscript`)
  означает, что каждый прогон стартует с чистой компиляцией исходников — ровно то, что нужно:
  мутированный файл подхватится при следующем запуске без каких-либо ухищрений.

### autumn — каркас и ограничение

- Типы компилируются движком при `#Использовать` / `ПодключитьСценарий`; «горячая» подмена
  уже загруженного типа в работающем процессе невозможна. Следствие: **один мутант = один
  дочерний процесс прогона тестов** (как pitest без агента — форк JVM на мутанта).
- Сам `mutatos` строим как autumn-приложение с autumn-cli (как OneUnit): команды-классы
  с `&КомандаПриложения`, DI-жёлуди, детальки для настроек.

## 2. Архитектура

### Конвейер (pitest-подобный)

```
1. Конфигурация      mutatos.json + CLI-аргументы
2. Базовый прогон    oneunit e --cobertura: проверка «зелёности», покрытие, эталонное время
3. Генерация         osparser: разбор каждого файла src один раз,
   мутантов          плагины-мутаторы собирают точки мутации (файл, позиция, длина, замена)
4. Фильтрация        отсев точек в непокрытых строках (NO_COVERAGE)
5. Исполнение        для каждого мутанта: применить замену -> прогнать тесты -> откатить
6. Отчёт             консоль + JSON + HTML (подсветка выживших мутантов в исходнике)
```

### Классификация мутантов (статусы как в pitest)

| Статус | Условие |
|---|---|
| `УБИТ` (KILLED) | exit code oneunit ≠ 0 |
| `ВЫЖИЛ` (SURVIVED) | exit code = 0 |
| `ТАЙМАУТ` (TIMED_OUT) | превышен лимит: `время_базового_прогона * КоэффициентТаймаута + Константа` |
| `НЕЖИЗНЕСПОСОБЕН` (NON_VIABLE) | мутант не компилируется; проверяется дёшево через `ЗагрузитьСценарийИзСтроки` до запуска тестов; исключается из знаменателя score |
| `БЕЗ_ПОКРЫТИЯ` (NO_COVERAGE) | строка мутации не покрыта тестами; тесты не запускаются, считается выжившим |

Mutation score = `УБИТ / (Всего - НЕЖИЗНЕСПОСОБЕН)`; таймаут считается убийством (как в pitest).

### Исполнение мутанта

MVP: мутация «на месте» — бэкап файла, запись мутированного текста, запуск
`oneunit e --mode none --timeout N [фильтры]`, восстановление из бэкапа (в `Попытке...`,
плюс восстановление по контрольной сумме при аварийном старте).

Параллельность (v0.2): N воркеров, каждый работает в своей временной копии проекта
(`ВременныеФайлы.СоздатьКаталог()` + копирование src и tests, oscript.cfg с путями к общим
`oscript_modules`); очередь мутантов раздаётся воркерам, процессы — через `ФоновыеЗадания`
или пул `Процесс`-объектов.

### Набор мутаторов (стартовый, по мотивам дефолтов pitest)

| Мутатор | Замена |
|---|---|
| ГраницыУсловий (CONDITIONALS_BOUNDARY) | `<` ↔ `<=`, `>` ↔ `>=` |
| ОтрицаниеУсловий (NEGATE_CONDITIONALS) | `=` ↔ `<>`, `<` → `>=`, `>` → `<=` … |
| Математика (MATH) | `+` ↔ `-`, `*` ↔ `/`, `%` → `*` |
| Логика (LOGICAL) | `И` ↔ `Или`, удаление `НЕ` |
| БулевыЛитералы | `Истина` ↔ `Ложь` |
| ЗначенияВозврата (EMPTY_RETURNS) | `Возврат X` → `Возврат Неопределено`, `Возврат Истина` → `Возврат Ложь` |
| ВызовыПроцедур (VOID_METHOD_CALLS) | удаление оператора вызова процедуры |
| ЧисловыеЛитералы | `0` → `1`, `N` → `N + 1` |
| СтроковыеЛитералы | `"..."` → `""`, `""` → `"mutatos"` |

Один мутатор = один класс-плагин osparser, регистрируется в DI как жёлудь с аннотацией
`&Мутатор` — сторонние библиотеки смогут добавлять свои мутаторы. Каждая точка мутации
получает стабильный идентификатор (файл + мутатор + позиция + порядковый номер) — основа
для инкрементального режима.

Осторожность в мутаторах: не мутировать внутри областей `#Удаление`, аннотаций и
аргументов `Сообщить`/логирования (настраиваемые исключения); для `+` учитывать
конкатенацию строк (мутация всё равно валидна, но `+`→`-` на строках даст NON_VIABLE в
рантайме, а не при компиляции — это нормально, упадёт тестом).

### CLI (эскиз)

```console
mutatos run [-s|--src ./src] [-d|--tests ./tests] \
            [--mutators Математика,Логика,...] [--exclude-files <regexp>] \
            [--threads N] [--timeout-factor 1.5] [--timeout-const 4000] \
            [--threshold 80]     # exit code 1, если score ниже — для CI
            [--json report.json] [--html mutation-report/]
```

## 3. Производительность

Главная стоимость — прогон тестов на мутанта (старт oscript + oneunit + компиляция исходников).
Меры, по нарастанию сложности:

1. **Отсев по покрытию** — не гонять тесты для непокрытых строк (v0.2).
2. **Отбор тестов на мутанта** — pitest использует матрицу «тест → покрытые строки»;
   у coverage/OneUnit покрытие агрегатное. Дешёвое приближение: запускать только тестовые
   файлы, в чьём транзитивном `#Использовать` есть мутируемый модуль. Точная матрица —
   прогон каждого теста отдельно с `-codestat` в рамках базового этапа (дорого, но
   однократно и кэшируется) — v0.3.
3. **Параллельные воркеры** в изолированных копиях проекта — v0.2.
4. **Инкрементальный режим** — кэш «хэш файла + хэш тестов → результаты мутантов»,
   пере-прогон только изменившегося — v0.3.
5. **Быстрая проверка компилируемости** мутанта через `ЗагрузитьСценарийИзСтроки`
   в самом процессе mutatos — NON_VIABLE отсекается без запуска тестов.

## 4. Риски

- **osparser 0.0.3 парсит язык 1С 8.3, не диалект OneScript на 100%** (директивы, `Новый` с хвостом
  и пр.). Митигация: нестрогий режим, обкатка на кодовых базах autumn/OneUnit как эталонных,
  PR с доработками в osparser; файлы с ошибками разбора — деградация до токен-мутаторов
  или пропуск с предупреждением.
- **Скорость**: интерпретируемый OneScript + процесс на мутанта. Митигации из раздела 3;
  честно позиционировать первый релиз для библиотек малого/среднего размера.
- **Эквивалентные мутанты** (мутация не меняет наблюдаемое поведение) — фундаментальная
  проблема мутационного тестирования; лечится подбором мутаторов и ручными исключениями
  (`// mutatos:off`).
- **Побочные эффекты тестов** при мутации «на месте» — обязательный откат в `Попытке`,
  контроль контрольных сумм, в перспективе только изолированные копии.
